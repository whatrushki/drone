# GEOSCAN FleetCommander AI
**Интеллектуальный сервис планирования и распределения беспилотных авиационных работ для группы БВС**

> Разработано в рамках хакатона «Лидеры Цифровой Трансформации 2026» для компании **АО «Геоскан»**.

---

## 🌟 Ключевые преимущества и инновации решения

1. **Модельная кинематика линейки БВС Геоскан**:
   - **Геоскан 201 (Самолет / Крыло)**: крейсерская скорость 21 м/с и построение переходов из дуг радиусом 85 м. Дискретизированный маршрут требует проверки в автопилоте перед полетом.
   - **Геоскан Gemini / 801 (Мультироторы)**: вертикальный взлет/посадка (VTOL), локальные развороты, повышенный учет энергопотребления при ветре.
2. **Аэродинамический навигационный треугольник скоростей (Wind Vector Triangle)**:
   - Вектор ветра $\vec{W}$ раскладывается на путевую скорость $V_{\text{ground}}$ и угол упреждения сноса (Crab angle).
   - Автоматический выбор оптимального азимута галсов вдоль направления ветра для минимизации крена и сноса камеры.
3. **Ограничения пространства**:
   - Загружаются 341 зона и 8 363 препятствия. Кандидат отклоняется, если полный маршрут пересекает буфер опасного препятствия или зону, для которой не доказано разделение по высоте. Неоднозначные высоты и время действия зон требуют проверки оператором; полноценного 4D-парсера пока нет.
4. **Поиск по двум целям**:
   - **Минимум времени (Makespan)**: минимум времени до завершения последнего БВС с учетом повторных вылетов и наземного интервала.
   - **Минимум суммарного налета**: минимум суммы времени всех БВС в воздухе.
   - Поиск сравнивает построенные маршруты для нескольких направлений галсов, составов флота, точек старта и разделений работ. Смещение сетки выбирается по покрытию. Он ограничен по времени и возвращает лучший проверенный вариант; доказательства глобального оптимума нет. API явно сообщает `optimality_proven: false`.
5. **Проверка результата**:
   - Контроль покрытия не менее 99% допустимой области, запаса батареи, полного маршрута относительно препятствий и зон. Дистанция, время и расход считаются по экспортируемой полилинии. Если допустимый вариант не найден, API возвращает объяснимый отказ 422.
6. **Выполнимость и сравнение сценариев**:
   - Сравнение одного борта и параллельного флота строится из реально рассчитанных кандидатов. Долгая работа разбивается на отдельные вылеты с возвратом к базе.
7. **Визуализация маршрутов**:
   - Карта показывает съёмочные проходы, транзитные участки и найденную альтернативу по другому критерию. Плеер интерполирует положение по рассчитанному времени каждого сегмента экспортируемой полилинии. Это демонстрационная симуляция, не сертифицированная 4D-модель.
8. **Экспорт**:
   - KML, GeoJSON и QGroundControl `.plan`; групповые задания выгружаются архивом с отдельным файлом для каждого вылета. `.plan` пока содержит навигационные точки без команд управления камерой и требует проверки в целевом ПО.

### Как выбирается маршрут

1. Из геометрии участка с сохранением внутренних вырезов строятся параллельные проходы для нескольких азимутов. Для каждого азимута проверяются пять смещений сетки; требуется покрытие не менее 99% области, оставшейся после исключения препятствий.
2. Для каждого проверяемого состава флота и точки старта проходы распределяются между БВС. Длинная работа делится на вылеты с возвратом к базе. При числе проходов до девяти порядок и направления перебираются точным динамическим программированием по *приближенной стоимости переходов*; на больших участках используется жадный маршрут с локальным улучшением.
3. Для каждого полного маршрута заново считаются расстояние, время при заданном ветре и расход батареи по экспортируемой полилинии. Недостаточное покрытие, нехватка энергии и пересечения с неподтвержденными зонами или опасными препятствиями отбраковываются. Победитель определяется заданной целью по допустимым маршрутам: временем завершения всей миссии с учетом наземных интервалов либо суммой времени БВС в воздухе.

Поиск ограничен бюджетом 12 секунд между кандидатами; отдельный сложный кандидат может увеличить время ответа. Он не перебирает все возможные распределения проходов, положения базы и непрерывные траектории. Для нескольких сенсоров задания строятся отдельно и затем ставятся в расписание с учетом общих БВС, поэтому совместный глобальный оптимум также не доказан. Автоматически предложенная база и маршрут требуют проверки оператором на местности и в целевом автопилоте.

## 🚀 Инструкция по быстрому запуску

### Требования
* Python 3.10+ (протестировано на Python 3.13)
* Браузер Chrome / Firefox / Edge

### Установка зависимостей
```bash
pip install fastapi uvicorn shapely geopandas pyproj scipy numpy pydantic
```

### Запуск сервиса
```bash
python run.py
```

После запуска откройте в браузере:
* **Веб-интерфейс**: [http://localhost:8000](http://localhost:8000)
* **Интерактивная документация Swagger API**: [http://localhost:8000/docs](http://localhost:8000/docs)

### Работа в интерфейсе

1. Найдите участок по FID в поле поиска или нарисуйте свой полигон. Список загружает все 613 объектов; выбор по индексу различает объекты с одинаковым FID. Площадь считается в проекции UTM.
2. При необходимости поставьте основную базу и резервные площадки щелчком по карте. Точки можно перетаскивать и удалять. Если их не задать, планировщик выбирает базу автоматически.
3. Если задана разрешённая область полётов, весь маршрут, включая перелёты и возвращение, должен находиться внутри неё. Планировщик проверяет это как жёсткое ограничение. Он не строит обходной путь вдоль границы, поэтому при отсутствии допустимого кандидата сообщит об отказе.
4. Выберите БВС, сенсор, GSD, ветер, критерий и при необходимости ограничения времени, числа бортов, перекрытия и наземного интервала. Нажмите «Сформировать задание». Для обоих критериев рассчитываются планы на одинаковых входных данных; карточки результата позволяют их сравнить и переключить. Подпись «лучший найденный» означает, что глобальная оптимальность не доказана.
5. Проверьте предупреждения, покрытие, маршруты и сценарий в плеере. Кнопки экспорта сохраняют отдельный файл для одиночного вылета или архив файлов для группового задания. Результат нужно проверить в целевом автопилоте и по актуальным ограничениям воздушного пространства.

## 📐 Математический аппарат

### 1. Фотограмметрия
$$H = \frac{F \cdot GSD}{s_p}, \quad D_{\text{swath}} = W_{\text{ground}} \cdot (1 - p_{\text{side}}), \quad B_x = L_{\text{ground}} \cdot (1 - p_{\text{forward}})$$

### 2. Вектор ветра
$$\vec{V}_{\text{ground}} = \vec{V}_{\text{air}} + \vec{W}, \quad \sin(\delta) = -\frac{W_{\text{cross}}}{V_{\text{air}}}$$

### 3. Радиус виража Дубинса для Геоскан 201
$$R_{\min} = \frac{V_{\text{air}}^2}{g \cdot \tan(\phi_{\max})} \approx 85\text{ м}$$

## 📋 Описание REST API
* `GET /api/catalog` — Справочник ТТХ БВС, камер и сенсоров.
* `GET /api/parcels` — Список участков из `Границы полетов.kml`.
* `GET /api/parcels/{fid}` — GeoJSON первого участка с указанным FID.
* `GET /api/parcels/by-index/{index}` — GeoJSON участка по индексу списка, включая дублирующиеся FID.
* `GET /api/airspace-zones` — 4D-зоны ограничений с высотами.
* `GET /api/obstacles` — Высотные мачты и вышки.
* `POST /api/preview-photogrammetry` — Мгновенный расчет высоты и шага съемки.
* `POST /api/plan-mission` — Полный расчет полетного задания для группы БВС.
* `POST /api/export/kml` — Выгрузка KML.
* `POST /api/export/geojson` — Выгрузка GeoJSON.
* `POST /api/export/qgc` — Выгрузка `.plan`.
